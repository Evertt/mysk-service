# Table improvements

What we're building for the app's data tables (`src/lib/components/data-table`), and where each item
stands. Status: ⬜ to do · 🔄 in progress (branch) · ✅ done (merged into `main`).

## Requested

| #   | Item                                                                                                                                                                                                                                                         | Status |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| 1   | **Table state in the URL.** Every filter, the search box, sorting and pagination of every table sync with the query string, in a readable grammar: `?status=quote,scheduled`, `?q=boiler`, `?sort=-scheduled,customer`, `?page=2&size=50`. Defaults omitted. | ✅     |
| 2   | **Server-side tables.** Orders, equipment and materials paginate, filter and sort in the database (remote queries), using the URL grammar from 1. The search box is debounced.                                                                               | ✅     |
| 3   | **Filters on related records**, e.g. the customer column on orders and equipment (and engineer, customer elsewhere), also for server-side tables.                                                                                                            | ✅     |
| 4   | **Popover close flicker.** Popovers and other overlays flash back to full opacity for a frame at the end of their exit animation.                                                                                                                            | ✅     |
| 5   | **Grouping rows by a column**, e.g. equipment by category or manufacturer, engineers by specialty, orders by type; also for server-side tables.                                                                                                              | ✅     |
| 6   | **Pinned columns and a scrolling body.** First (identifying) column pinned left, actions pinned right; the table body scrolls with a sticky header so the pagination is never below the fold.                                                                | ✅     |
| 7   | **Better sorting.** Ascending → descending → unsorted, and sorting by several columns at once (shift-click), with each column's precedence shown.                                                                                                            | ✅     |

| 21  | **Stable column widths.** Paging through a table doesn't change its column widths; they come from the data the table has shown, without any column configured as fixed. The table keeps, per column, the rows with the widest cells it has seen, rendered as hidden rows (no height, inert, hidden from screen readers) so the browser lays the columns out as if all that data were there. A filter, search or sort lays the new rows out with them; a page change freezes the widths while the hidden rows keep learning, so the widths converge to what the table would pick with everything seen loaded at once. Columns whose values are known up front start right: options from a filter's `oneOf` (the widest label in the current language) and dates (the widest date in the cell's format); near-uniform columns (amounts, codes) settle by measuring. The memory starts over when columns are hidden or shown, or the density or language changes, and lasts a visit (`sessionStorage`). Works for tables that fit the page and for those that scroll sideways. If the hidden rows don't work cleanly, the fallback is a default page size of 100 and widths frozen after the first load. | 🔄 `table-columns` |
| 22  | **The last view comes back.** Opening a table's page without table parameters in the URL brings back the user's last state there: the saved view they had open, with any unsaved edits still shown as unsaved, so leaving a page never loses them (no "unsaved changes" warning). A link with parameters wins; choosing no view or resetting clears it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 🔄 `table-columns` |
