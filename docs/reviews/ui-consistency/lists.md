# Review: office LIST pages (reviewer `lists`)

Looked at desktop + mobile shots of orders, customers, engineers, equipment, materials, invoices, credit-notes, contracts, maintenance, parts-shop, parts-shop-products, checklists, condition, activity, and the interaction states (orders, equipment filter/view/saved/selected). Code refs from code-system.md plus toolbar-band.svelte, units-table.svelte.

## Verdict on the central question

**Do not roll the band + chips out to every list; take it off /equipment.** Reasons:

- The standard list (PageHeader + ListToolbar + table) is already the majority (10 of 14 lists) and is calm, dense and scannable.
- Chips duplicate the toolbar's Category facet (the code comment at category-chips.svelte:5-7 admits it). Most lists have no single dominant dimension that deserves chips (invoices: status; orders: status/type; contracts: status/level). A band per list would mean a second, louder filter UI on every page.
- The band costs ~170px (desktop) and ~400px (mobile: equipment mobile shows band + 11 chips before the search box) before the first row. On a 514-row operational list that is the wrong trade.
- What IS good: the one-glance count ("514 units"), and a fast single-dimension filter. Both can be done inside the standard toolbar (see recommendations).
- Condition's KPI tiles as filters are the better idea of the two, but only where the numbers mean something different from a row count (health: critical / attention / planned / in order). Keep them as a _summary strip_ on condition only, rendered by a shared component (see 4).

## 1. Per-page notes

**orders** (`orders.png`, `orders--*`): standard. At 1440 with the sidebar the table is wider than the card: Engineer column is cut off at the right edge with a sticky "..." column over it (no visible scroll cue except the clipped text). Status is an inline-editable badge with a chevron (dropdown look inside a badge) - unique to orders/engineers; Priority and Type use yet other styles (arrow-icon badge vs plain text with icon). Row density: two-line cells, 53px rows, good. Filter menu is a flat list of 9 facets, no search, no grouping. Selection bar ("100 selected", Assign engineer / Change status / More) floats at the bottom of the card: good, clear. Select-all selects 100 rows silently (page size) - the bar says 100 selected while the list has more.
**customers / engineers / materials**: the cleanest pages; they are the reference. Segment and Specialty are outline badges with icons (customers/engineers) while materials' stock states are warning/destructive tinted badges only when abnormal ("Low", "Out of stock"): good pattern (show status only when exceptional).
**equipment**: band + count pill + chips (two wrapped rows at 1440, 11 chips). Under the band the standard toolbar repeats. Filter menu starts with "Manufacturer" highlighted and "Category" second: the facet that the chips duplicate is still there. Status column shows "Operational" green on ~90% of rows: noise; the exceptional ones (Needs service, Decommissioned) are what matter. Table also overflows (Location cut off).
**invoices**: the standard list, but the header carries three actions (Credit notes, Settings, New invoice) which wrap on mobile into two rows. Status badges small, with icons (Draft/Sent/Paid/Void) - consistent with the lagoon tinted badge. Amount column right-aligned: good. "Credited" column is empty on nearly all rows (header present, no values in the screenshot).
**credit-notes**: standard, with breadcrumb (Invoices > Credit notes) above the title, so the title sits ~36px lower than on invoices. Back-navigation idiom differs from sibling top-level lists (none). Negative amounts right-aligned: good.
**contracts**: standard; three adjacent badge columns (Level outline, Status tinted) at similar visual weight; Expired rows are the same size as Active, no de-emphasis. Period + "1 year" two-line cell is good.
**maintenance**: unique toolbar: Filter + "Reset x" + a period Select ("Overdue and the next 30 days") on the right between search and Saved views. **parts-shop (Shop orders)**: not a ListLayout: hand-built table in a Card with an inset header row, FilterChips Open/All as a view switch, no search/Filter/Saved views/View. The card padding is double (card border + inset table), rows 36px. Header action "Shop products" is outline/secondary where other pages' primary is teal.
**parts-shop-products**: raw Table in Card, with breadcrumb; no toolbar at all; row action is a visible "Edit" outline button on every row (other lists use the "..." menu); "In the shop" column packs 3-4 mixed badges (per piece / Parts credit / Popular / points) in unrelated colours (grey outline, green, blue). ## 2. Numbered inconsistencies

1. **Title area: three fills.** equipment (ToolbarBand, h1 text-xl, count pill), condition + checklists (PageBanner, uppercase eyebrow "CONNECT" on condition only, h1 text-2xl), everything else PageHeader. Majority/best: PageHeader. Equipment's band even uses a smaller h1 than the plain pages. Severity: high (jarring when moving between sidebar items "Equipment" -> "Customers" -> "Components").
2. **Filter UI dialects (6).** (a) ListToolbar Filter menu [orders, customers, engineers, materials, invoices, credit-notes, contracts]; (b) + category chips [equipment]; (c) + KPI tiles + customer chips + checkbox [condition]; (d) own search + select + chips in a side list [checklists]; (e) chips only, no search [parts-shop]; (f) form with native selects/dates + submit [activity]; plus (g) maintenance's period select + Reset. Best: (a). Severity: high.
3. **Raw tables vs ListLayout.** parts-shop, parts-shop-products, activity (feed) and checklists templates are outside the list kit: no search, no column toggle, no saved views, no density, different row height and header style (parts-shop header cells are tiny uppercase-less grey on an inset band; products rows are 49px). Severity: med-high (parts-shop products is a 14-row catalogue that would profit from search and sort).
4. **Duplicated facet.** equipment's category chips = Category in Filter menu. Chips carry counts (good) but the Filter menu shows no counts. Severity: med. See recommendation 2.
5. **Status display: five styles.** (i) tinted badge with icon (invoices, contracts, credit notes); (ii) badge with chevron = inline-editable (orders, engineers) - looks like a button but sits next to read-only badges; (iii) tint-only text badge without icon (equipment "Operational", parts-shop "Confirmed"); (iv) outline badge (Segment, Level, Specialty, checklist "2026 open"); (v) badge+dot+bar (condition). Equipment/contracts show the _normal_ state in green on every row. Best: invoices (icon+tint). Severity: med-high.
6. **Row action idiom.** "..." menu on all ListLayout lists vs visible "Edit" button (parts-shop-products) vs none (parts-shop orders, activity, condition, checklists). Severity: low-med.
7. **Header action placement/wrap.** Primary "New x" is top-right on desktop everywhere; on mobile it falls under the subtitle as its own row and pushes the toolbar down ~50px (orders, customers, materials, contracts). invoices mobile stacks 3 buttons in 2 rows, maintenance shows Settings alone. Secondary header actions (Settings, Credit notes, Shop products, Templates, Activity log) are outline buttons in some pages, "secondary" white buttons on banners (condition/checklists), plain text-weight buttons elsewhere. Severity: med.
8. **Breadcrumbs on sub-lists only partially.** credit-notes and parts-shop-products have breadcrumbs (title +36px), sibling lists don't; orders/customers have none. That is correct hierarchy but the shift reads as inconsistent; parts-shop (parent) has no cue to its child except an outline button "Shop products". Severity: low.
9. **Tables overflow at the standard viewport.** orders (Engineer clipped), equipment (Location clipped), condition (Advice clipped), mobile all. The sticky action column covers the clipped cell, and there is no fade/scroll hint on desktop (fade-edges.ts exists - not visible in the shots). Severity: med. Default column set is too wide for 1440 minus the 256px sidebar; Density/columns exist but defaults aren't tuned.
10. **Mobile: tables only scroll sideways.** All lists show 2 columns (code + customer) then clip; no card/list mode. Core info (status, priority, amount) is invisible without scrolling. Severity: high for engineers/planners on a phone; it is the same on every list so it is at least consistent.
11. **Mobile toolbar.** Search full-width, then Filter | Saved views | View on a second line: good and consistent (best part of mobile). Exceptions: maintenance (select + Reset wrap to 3 lines), invoices (search drawn with a border in one shot vs filled in others - low), equipment (band + 11 chips = 400px of chrome), condition (explainer + tiles).
12. **Empty-ish regions.** checklists right pane = "Pick an asset" large empty card; parts-shop page = 1 row then 500px of blank; credit-notes 4 rows (fine). Severity: low-med.
13. **Activity page filter** is a Card with native controls and mixed language ("dd/mm/yyyy"); machine entries dominate. Severity: med.
14. **Condition's three health encodings** and the unlabeled dot (see page notes). Severity: med.
15. **Chips colour logic.** FilterChips active state = teal outline/tint (equipment on a band, parts-shop on the page); inactive chips on a band look slightly grey-on-white but are borderline low contrast (count numbers in muted grey ~#9ca3af on white). Severity: low.
16. **Row density consistent (~53px two-line) on all ListLayout lists** - good, but parts-shop products (49px with big pill clusters) and maintenance (two-line with truncated plan names "(NE...") differ. Low.
17. **Page-title vs nav naming**: checklists "Digital checkpoint work order" (title) / "Work orders" (nav + tab); condition "Components per customer" / "Components"; parts-shop "Shop orders" / "Parts shop". Med: breadcrumbless pages rely on the title to orient.
18. (Capture artefact?) `parts-shop-products.png` was taken with the sidebar collapsed; not a design issue.

## 3. Worth keeping

- **ListToolbar** (search | Filter | ... | Saved views | View with columns/group by/density): excellent and uniform; mobile layout is good.
- **Selection bar** pinned to the card bottom with Assign / Change status / More.
- **Materials "Low" / "Out of stock" badges**: show a state only when abnormal.
- **Condition's KPI-as-filter tiles**: the number + coloured icon + big figure is the best "at a glance" element in the office app. Condition's condition bar (% + coloured meter) is a clear numeric scale.
- **Equipment's band count pill** ("514 units") and the category counts: worth having - but as a count under/next to the title and as counts in the facet.
- **Invoices' icon+tint badges**, right-aligned currency, two-line "primary + muted secondary" cell (name / customer code, unit / model·serial): consistent and scannable.
- **Maintenance's period select** as a quick scope (Overdue and the next 30 days) next to the toolbar: this is the right kind of quick filter (a time scope, not a duplicate of a facet).
- **Checklists asset list**: year-badge ("2026 ✓" / "2026 open") per row: compact status.

## 4. Recommendations

1. **Remove the ToolbarBand from /equipment; use PageHeader.** Move "514 units" into the PageHeader (a `count` badge next to the title, usable on all lists), keep `New unit` as the primary. Delete CategoryChips; instead make the Category facet in the Filter menu the first item with counts, and render active filters as removable pills under the toolbar (filter-pill.svelte already exists). Frees ~170px.
2. **Offer an optional shared "quick filter" row (`ListQuickFilters`) for lists with ONE dominant enum** (condition: health; orders/invoices: status): a single row of chips or KPI tiles bound to the same column filter, one component with counts, replacing equipment chips, condition tiles+checkbox, parts-shop Open/All, activity selects. Default off; max one row, ≤6 items, overflow into the Filter menu. This keeps the best part of the band without making every page loud.
3. **Bring parts-shop, parts-shop-products and checklists template/asset lists onto `ListLayout`** (search, Filter, View, row "..." menu instead of Edit buttons); for checklists, keep the master/detail but use the ListToolbar for the left column; drop the banner for PageHeader. Rework activity filters into a ListToolbar-like row (Record type, User, date range via the existing date-range-filter.svelte).
4. **One status vocabulary:** EnumBadge tint+icon for state; plain text/outline only for categories (Level, Segment, Specialty, Type); inline-edit badges get a hover affordance instead of a permanent chevron; show the "normal" state quietly (muted text/dot) and exceptional states in colour; collapse condition's badge+dot+bar to badge+bar.
5. **Fix the width and the phone:** tune default columns to fit 1440 minus sidebar (orders, equipment, condition), show a fade/scroll cue on the clipped edge; on mobile put the primary action in the header row beside the title (icon-only "+" or compact button) and consider a two-line card row (primary, status, secondary) below 640px; trim condition's explainer behind a "How it works" disclosure that stays closed after first visit.
