# Code survey: styling system and page-level inconsistencies (Fieldworks)

## A. Map of the system

**Themes** (`src/lib/themes/`): six themes (`neutral, harbor, lagoon, blueprint, brutalist, sorbet`, index.ts:13), `DEFAULT_THEME = "lagoon"` (index.ts:25). A theme = CSS vars (`vars`/`darkVars`) + per-`data-slot` class overrides (`components`, slot names generated into slots.ts). Themes cannot add components; they only restyle shadcn parts by slot. Lagoon (lagoon.ts, 158 lines) is a port of the SHLTR client mockup: slate/teal oklch tokens, `--radius .625rem`, badge restyled to small square tinted pills (lagoon.ts:96-109), card "section" style (header band + teal bar before the title via `has-[>card-header+card-content]` selectors, lagoon.ts:118-130), muted input fills, `shadow-none`. No `shltr`-specific styling exists in src: "shltr" is only a seed tenant (tests, seed, `models.ts`); the SHLTR look reaches the UI through (a) the lagoon theme and (b) shared components whose doc comments say "as the SHLTR mockup": `ToolbarBand`, `PageBanner`, `FilterChips`, `Callout`, plus module-only visuals (energy `HeroBanner`, `KpiTile`, `building-overview`, `door-card`, docks `dock-drawing`). Those components are theme-independent (use `bg-primary`) so they show in every theme.

## B. Inconsistencies (numbered)

1. **Four different page-title components in the office app.** Majority (about 50 pages, incl. every list but two): `PageHeader` = plain heading text-2xl + muted description + `Button`s right. Deviants: `ToolbarBand` (equipment, schedule; h1 `text-xl` at toolbar-band.svelte:56, solid brand fill, icon, count pill), `PageBanner` (docks, condition, checklists assets; gradient, uppercase eyebrow, h1 text-2xl), energy `HeroBanner` (hero-banner.svelte, hard-coded `text-white`, own gradient with different darkening 24%/64%, breadcrumbs inside the banner). Three different gradient/fill recipes: toolbar-band.svelte:49, page-banner.svelte:36, hero-banner.svelte:69. Banner pages pass `variant="secondary"` buttons, band pages `bandButton` ghost, normal pages default/outline buttons, so the primary action looks different on each.

2. **Equipment list is the only core list with a band + chips.** orders/customers/engineers/invoices/materials/contracts/maintenance/partners use `PageHeader` + `ListLayout` (see "Pages" kit section). `/equipment` (routes/(app)/equipment/+page.svelte:35-57) uses `ToolbarBand` with `CategoryChips` (equipment/list/category-chips.svelte) passed through `EquipmentTable`'s `header` snippet; the chips set the same `category` column filter that the toolbar's Category filter sets (comment at category-chips.svelte:5-7 admits the duplication). Unit count is shown as a band pill; no other list shows its row count that way. `<title>` is hand-written there (+page.svelte:35-37) because the band does not set it.

3. **Extra filter UI around list tables, not uniform.** Standard: only `ListToolbar` (search + Filter menu). Extras: equipment category chips (above); condition units list has a KPI-tile row that doubles as status filter (View buttons with `aria-pressed`, units-table.svelte:116-146), customer `FilterChips`, and an "only needs attention" checkbox (units-table.svelte:150-163) above the toolbar; checklists `AssetList` has its own search box + chips in a 320px left column (checklists/assets/asset-list.svelte:88-120); parts-shop orders page has `FilterChips` view switch (parts-shop/routes/(app)/+page.svelte:`FilterChips label={m.shop_orders_view()}`) and a hand-built `Table` in a Card, not a defined list; parts-shop products, partner-programme settings, templates-table (checklists/list/templates-table.svelte), energy settings, ops bug-reports and activity use raw `Table.Root` (about 35 files use `<Table.Root>`, 12 tables use `ListLayout`). Activity page has a GET form with native selects/date inputs in a Card header (activity/+page.svelte:~40-110), a third filter style. Customer portal orders uses `FilterChips` as tabs (portal/orders/+page.svelte:60).

4. **Lists shown as cards/grids instead of tables:** energy index sites grid (energy/routes/(app)/+page.svelte:`ul grid`), customer portal equipment (cards per site), docks board, parts-shop customer portal product cards, schedule board/month. Core `customers` list is a table although a `customer-card.svelte` exists (lib/customers/ui).

5. **Hand-rolled `<h1>` + `<svelte:head><title>` instead of PageHeader** (kit says PageHeader titles the tab): dashboard (routes/(app)/(dashboard)/+page.svelte:88), all customer-portal pages (portal/+page.svelte:33, orders:58, equipment:21, report:74, locations:25, orders/[number]:73, equipment/[serial]:42), field portal (my/+page.svelte:23, my/[number]:97, my/locations:25, my/equipment:26), shop portal (parts-shop portal +page.svelte:105, orders:27, orders/[number]:47), energy portal (:57) and energy report (:109, `text-2xl font-semibold` without `tracking-tight`), checklists work-order (detail/work-order.svelte:42), labels page. 27 files carry `<svelte:head>` in +page. Portals have no breadcrumbs; they use ad-hoc back buttons with `ArrowLeftIcon` (checklists work-orders :28, portal work-orders :34, my/[number]:92, activity:166, labels:47). Office detail pages use breadcrumbs instead (31 pages with `breadcrumbs=`; 13 `PageHeader` pages without, i.e. all top-level lists).

6. **Heading scale.** Page h1: text-2xl (21 hand-rolled/PageHeader) vs `text-xl` ToolbarBand vs hero-banner `text-2xl` over white. Card titles: lagoon sets `text-sm` for header+content cards but default for header-only cards (lagoon.ts:122-126), so card titles are different sizes depending on card structure. h-tag classes found: `text-lg font-semibold` (6), `text-base font-semibold` (2), `text-sm font-semibold` (5), `text-sm font-medium text-muted-foreground` (10), `text-xs ... uppercase` (5) with and without `tracking-wide`.

7. **Hard-coded palette colours (kit: use `success/warning/info/destructive` tokens; guard `state-colours.spec.ts` allows exceptions per file).** Files with raw palette classes (count): schedule/calendar/type-colors.ts (27; an order-type colour set, allowed), docks/board/dock-drawing.svelte (19, plus 10 hex fills :49-:194), energy/overview/door-card.svelte (12 + hex `#cbd5e1/#94a3b8/#64748b/#475569` at :193-198), energy/building-overview.svelte (6; slate-800 header bar with `text-teal-400` at :140-142, `rgb(255 255 255 / .28)` at :273), energy/consumption-chart.svelte (3; `bg-amber-500`, slate-300), docks/board/components-card.svelte (5), docks/display.ts (3), energy/display.ts:58, ui/badge/badge.svelte:22-26 (metal colours for partner levels), docks beacon-light. Hard-coded `text-white`/`bg-white/15`: hero-banner.svelte:69-110, energy [site]/+page.svelte:197 (`text-white/75`), simulation-badge.svelte:21, `dark:bg-white` in segmented-nav.svelte:46, toolbar-band.svelte:49. Energy and docks are the heaviest, i.e. the module visuals copied from mockups; the energy hero uses fixed white text, whereas ToolbarBand/PageBanner use `text-primary-foreground`, so on a light-primary theme the hero would be unreadable.

8. **Font sizes outside the scale:** 13x `text-[0.6875rem]`, 12x `text-[0.625rem]`, 2x `text-[11px]`, singles `text-[8px]`, `text-[7px]`, `text-[0.5rem]`, `text-[0.5625rem]` (mostly energy/docks drawings, StatTile trend `text-[11px]` stat-tile.svelte:`text-[11px]`, lagoon badge `text-[0.6875rem]`, lagoon.ts:98). Lagoon's badge is 11px; base badge text-xs and `rounded-4xl` pill; lagoon makes it `rounded-[0.25rem]` square, so badges are pill in other themes but square in the default.

9. **Radii and shadows mix.** Counts: rounded-md 71, rounded-lg 53, bare `rounded` 44, rounded-sm 20, rounded-xl 13, rounded-full 36. Banners/bands/callouts/StatTile use `rounded-lg`; lagoon cards `rounded-md` (lagoon.ts:120); lagoon dialog `rounded-lg`; `--radius` 0.625rem, so "rounded-md/lg" are not consistent with the 8px the theme comment promises. Shadows: lagoon strips card shadows (`shadow-none`) but adds `shadow-sm` on default/outline buttons (lagoon.ts:134-136); shadow-md/lg/xl used in a few overlays and the energy/docks drawings.

10. **Stat/KPI tiles: five StatTile layouts plus a hand-rolled one.** `StatTile` layouts `inline` (condition), `stacked` (dashboard), `row` (customer card), `card` (detail pages), `figure`. Energy has its own `KpiTile` (energy/overview/kpi-tile.svelte, tone passed as a raw class string e.g. `tone="text-primary"`), used in a 6-column grid on the site page; docks board and condition also wrap tiles in `div.contents` for tests. Different grids: condition `xl:grid-cols-5`, energy `xl:grid-cols-6`, dashboard own grid. Energy `consumption-chart`, `detail-panel`, `door-card` also draw their own bordered boxes (`rounded-lg border border-slate-300`) instead of `Card`.

11. **Card idioms.** Lagoon's section card (header band + teal bar) only applies when a `Card.Header` is directly followed by `Card.Content`. Cards with header only, content only (activity filter card, shop orders `Card.Content` only, energy index empty state `Card.Content` with just `<p>`), or footers look different. Also hand-built bordered boxes instead of Card: portal equipment location links (`rounded-md border px-2.5 py-1`), energy building-overview, `Callout`, `Empty.Root class="border"` (checklists :~40, docks, portal orders) vs `Empty.Root class="p-6"` inside a Card (shop orders) vs no border (data-table).

12. **Page widths and padding.** Office shell: no max-width, `p-4 md:p-6`, so tables and forms go full width. Form/settings pages self-limit with ad-hoc widths: `max-w-2xl` (credit-notes/new:41, partner settings:38, shop settings:37, portal report:72), `max-w-3xl` (equipment-categories:25, shop portal order:62), `max-w-4xl` (order-types:25, energy thresholds:25), `max-w-5xl` (energy setup:56, report:81); `RecordForm` and `RecordPage` set none (grep of `max-w` in components/form and record-page.svelte: nothing). Customer portal `max-w-[1400px]`, ops `max-w-7xl`, field `max-w-xl`. Gaps: office pages use a `flex-col gap-6` from shell, but several pages wrap again in `flex flex-col gap-6` (docks, checklists, energy index) and energy site uses `gap-4`.

13. **Single-choice controls used three ways.** `FilterChips` as filter (equipment, condition, energy floors), as tabs/views (shop orders `view`, portal orders `tab`), and as a scope selector (energy). `SegmentedNav` used for views (schedule, energy period). `Tabs` only in partner-programme client (the kit says tabs are refused by `choice-controls.spec.ts`; check it is allow-listed). The energy site page has chips and a segmented control on one row (`ml-auto`), unlike any other page.

14. **Status/enum display.** Majority: `EnumBadge` with tone from a `*Display` map, and `column.enum()` in tables. Deviants: (a) plain-text badges for enum values: `<Badge variant="outline">{label("orderStatus", …)}</Badge>` in checklists/assets/office-checklist.svelte:137 (not EnumBadge); (b) `Badge variant="secondary"/"outline"` used as status-like labels: maintenance "paused" (detail/plan-row.svelte:56, slots/contracts.detail.side/plans.svelte:46), checklists "retired" (settings/[id]:53), module-card "always on/disabled" (settings/module-card.svelte:59-66), "expired" `destructive` (members invitations-card:56), docks "no state" (dock-card:86, dock-state:64); (c) coloured dots + text: energy `toneColours` dots (building-overview.svelte:105,132), docks `BeaconLight` with raw `bg-emerald/amber/rose` lamps (docks/display.ts), hero-banner live dot (hero-banner.svelte:93), docks banner live dot with inline `color-mix` (docks/routes/(app)/+page.svelte:40), calendar order-type swatches (schedule/calendar/type-legend.svelte:20); (d) condition status via `status-badge.svelte` (own wrapper) plus StatTile tones. Partner levels use the metal-colour badge variants (badge.svelte:22-26), a second colour system next to the tone variants. Lagoon restyles `secondary` as info-tinted (lagoon.ts:100), so neutral labels like "Paused" and counts look blue/info in the default theme while EnumBadge "info" is the same colour, so they are indistinguishable.

15. **Lagoon overrides conflict with base components.** Lagoon changes `badge.default` to a tinted teal (not solid), `secondary` to info-blue, so Badge variants mean different things per theme; `data-table` `rounded-md bg-card`; card titles get a teal accent bar only in section cards. The band/banner components are not themed per slot (no `data-slot`), so other themes cannot restyle them, and they all derive from `--primary` with `color-mix(... black 12/24/50/64%)` in four places (toolbar-band.svelte:49, page-banner.svelte:36, hero-banner.svelte:69, segmented-nav.svelte:46).

16. **Sheets vs dialogs vs pages for forms.** Create/edit of core records and module records: dedicated pages with `RecordForm`. Small records (sites, locations, categories, stock, plans, docks, zones): `FormDialog`. Only one `Sheet` in the app (condition feed history, condition/routes/(app)/+page.svelte:`Sheet.Root`), built by hand next to the kit's "dialogs are FormDialog/ConfirmDialog" rule; a sheet has no shared wrapper.

17. **Empty states.** `Empty.Root` is used directly in ~40 places with varying decorations: with `Empty.Media variant="icon"` (portal orders), without (shop, docks, checklists), `class="border"`, `class="p-6"`, or a bare `<p class="text-sm text-muted-foreground">` in a Card (energy index `energy_no_sites`). No shared empty-state component.

18. **Page-level extras that duplicate other places.** Condition and docks pages stack extra strips under the banner (`ProcessSteps`, `StatusLegend`, `SimulationBar`) with no common "page intro" slot; `SimulationBar` appears on docks and energy site only.
