# Portals review: customer portal (/portal, module portal pages) and engineer portal (/my)

Verdict: not three styles but 2.5. All three share tokens, Card, EnumBadge and the lagoon teal, so they read as one brand. They diverge in shell, page header, back navigation, list form and wallet/KPI idioms. The engineer portal is the most coherent and phone-appropriate; the customer portal is the office app minus the toolbar; the module portal pages (partner programme, parts shop, energy) each bring their own mini-design.

Note on screenshots: `my.png` (desktop) is a phone-frame mock ("Engineer portal: how engineers see it on their phone", routes/(field)/phone-frame.svelte) and the full-page capture is mostly blank except the frame. A good idea, see "Worth keeping".

## 1. Per-page notes

**my (mobile)**. Slim sticky header (logo tile + engineer name + org, bell, kebab), one column `max-w-xl p-4` ((field)/+layout.svelte:58). h1 "My work" text-2xl, day sections as `text-sm font-medium text-muted-foreground` heading with count, then `WorkCard`s (rounded-xl, shadow-xs, big bold time, order number right, customer, pin + city, description line-clamp-2, two EnumBadges, chevron). Good tap targets, clear hierarchy. Problems: 9,356 px long with 14 "Today" cards plus many days: no sticky day headers, no jump-to-today, no "next up" emphasis; "In progress" job looks the same as the rest (only a small amber badge). Card corner radius (rounded-xl) and shadow-xs differ from the Card (rounded-md, shadow-none in lagoon) used on the same screen type elsewhere.

**my-order (mobile)**. Back link is a ghost `sm` Button "← My work" (my/[number]/+page.svelte:91), then order number (small), h1 customer name, date line, status/priority badges + order-type text (the type "Project" is plain text with folder icon, not a badge: inconsistent with the badges beside it). Then 6+ section Cards (The job, Site, Customer, Labour, Materials, Notes, Complete job). Strong mobile pattern: full-width Call/Email buttons, primary teal actions "Save hours", "Save materials", "Complete job" full width. Issues: "Save hours" and "Add note" / "Add material" are default-size buttons (h-9, about 36px) on a phone; Add material (outline) and Save materials (primary) sit side by side with equal weight; empty states are plain text ("No materials used yet.", "No notes yet.") inside cards; no sticky primary action (Complete job is ~2,800 px down); card headers carry the lagoon teal accent bar even for simple forms, adding noise. Labels in "Site" are tiny muted `text-xs`, values 14px: fine.

**my-equipment / my-location (mobile)**. Same header pattern as order. h1 + status badge beside it (my-equipment) vs h1 only (my-location). Both open with the text "Your open orders here" (`text-sm muted` section heading, same as day headings) then a WorkCard, then Cards. Consistent within the portal. No back button visible in screenshot (my-order has one; equipment/location detail pages reached from an order would need one): check `my/equipment/[serial]`/`my/locations/[id]` back handling.

**portal (home)**. Desktop: sidebar + top bar (customer name + "signed in as", language, theme (Lagoon), view-as, sign-out), h1 "Customer portal", primary "Report a breakdown" on the right, then three different surfaces stacked: "Units needing attention" (bordered list), a white "Partner bonus 2026" card beside a navy "Parts credit / Wallet" card, then "Open orders · 26" as a table-in-card and "Recently completed". The home page is a dashboard of module teasers without hierarchy: nothing says "this is what matters now". The dark navy wallet card (also on /partner-programme/portal) is the single darkest, heaviest element in the whole product. Mobile: orders become cards, "Open orders" heading is `text-sm muted`, fine, but home is 6,463 px long and the wallet and bonus blocks (money) sit between attention units and orders.

**portal-orders**. Chips (Open 25 / Completed 167 / All 200) act as tabs. Desktop = real table in a rounded card with Number/Order/Status/Date and a chevron; mobile = cards. Rows show number as plain `ORD-…` black text, title `Breakdown · Sectionaaldeur laadd...` with the type prefix. On mobile the title is truncated to ~20 characters ("Breakdown · Automati…") while the description gets two full lines: the unit name, which is the thing a customer recognises, is the part that is cut off. Rejected order shows its rejection reason in red body text (good, but red text on a white card without an alert container).

**portal-order**. Back link "← Orders" (ghost sm Button), h1 `Breakdown` + muted order number (the only page that splits the title in two weights), status badge right, description as large body text, then Units card + a bare key/value Card (no header, so no accent bar) on the right. No activity/timeline, no engineer contact. Compared with office record pages (RecordPage with breadcrumbs, 2 columns, activity), this is a hand-built cousin.

**portal-report**. Form capped at ~670px, left-aligned in a 1,100px-wide area (empty right half). Urgency radios are native-blue (`accent` colour not themed: blue dot on a teal-tinted selected card, portal-report-d: the radio is #1a56ff-like while everything else is teal). Primary button with send icon, left aligned. OK form, but not in `RecordForm` look (no card).

**portal-equipment**. One Card per site with a wrapped cloud of ~22 location chips (outlined pills, 5 rows on mobile) above the unit list. The chips are links to locations but look like FilterChips (same shape, no counts). On mobile the chip cloud takes the whole first screen before any unit shows. Units list: name, subtitle (make · serial · category · location) truncated, status badge right. Hairline rows inside the card are rounded-md, with the last row's border showing a small radius artifact (rows have shadow-like bottom edge).

**portal-equipment-detail / portal-location**. h1 + status badge, grey subtitle, then a standalone primary button "Report a breakdown" (here) / "Report a breakdown here" under the title instead of in a header action slot. Equipment detail has no back link and no breadcrumbs, the order detail has one: back navigation differs per page. Equipment detail has an "Inspections and maintenance" card with a title in the card header but no accent bar (different card recipe than "Units" card on portal-order), and a section heading "Orders on this unit" (`text-sm muted`) above a table-in-card. Location page: a single unit card with no header, nothing else; very empty at 1440.

**portal-energy**. Heading + subtitle + SegmentedNav (Today/This month, the only primary-filled segmented control in the portals) + KPI cards. KPI cards use the lagoon header/content card split, so each has an empty body (see the two cards with a blank bottom half): header strip with icon + label, teal accent bar before the value, footer with comparison. Cards of unequal content show big empty areas. Different KPI form from the dashboard's `StatTile` (icon above big number). Mobile: 2-col KPIs, fifth card alone; chart card header has a bar + title wrapped into 3 lines because the legend takes the width.

**portal-partner-programme**. The only portal page with a hero (`PageBanner`, teal gradient, eyebrow, claim headline). It replaces the h1 (the h1 is the marketing claim "Growing together. More in return.", while the sidebar says "Partner bonus"), so the page has no plain title. Next: a white Card with tinted KPI tiles (accent left border) and two inner boxes (cash vs parts credit, the second teal-tinted), a navy Wallet card with its own list, "Closed years" cards with a metal-yellow GOLD+ badge. Visually the richest, and with the home wallet and the shop wallet banner it forms three "wallet" renderings (navy card, light teal banner, inline row).

**portal-parts-shop**. Header with ghost-outline button "Your shop orders" (outline here, ghost "Orders" back-link elsewhere), a light-teal wallet banner (Callout), an amber low-stock Callout, then search + FilterChips + product cards and a sticky cart card. Product cards: header (code mono + title with accent bar) and a body; card top rows are misaligned between columns (SD-001 has a "Popular" badge that pushes the title down 4px, so the two cards' bodies start at different y). Mobile cart is below the products (not visible in screenshot), so "Pay with parts credit" is far from "Add". Callout colours: wallet = teal, stock warning = beige/amber, both with 1px border and rounded-lg, a third alert style next to the destructive text and Alert elsewhere.

**portal-parts-shop-orders / -order**. Orders list is a table with no header row (number, date, badge, amount; different from portal-orders' table with a header row and chevron). Order detail: header plus a card narrower than the page (max-w-3xl), copy "Placed 21 Aug 2026, 00:00 by someone" (placeholder-like text, bug), and the back control is a button "Your shop orders" below the content instead of a "←" at the top as on portal-order.

## 2. Inconsistencies

1. **Three page-header treatments across portals, none is `PageHeader`** (high). All portal pages hand-write `<h1 class="text-2xl font-semibold tracking-tight">` (src/routes/(customer)/portal/_, (field)/my/_, modules/_/routes/(customer)/portal/_); energy portal drops `tracking-tight` (energy/routes/(customer)/portal/+page.svelte:57); partner programme replaces the h1 with a PageBanner claim; order detail splits the title in two weights; shop order uses the number as title. Actions sit in four places: top-right (portal home, parts shop), below the title as a standalone button (equipment detail, location), inline status badge top-right (order, shop order, equipment detail), nowhere. Best variant: the office `PageHeader` (title + muted description + actions right); the portals should use it (it also sets `<title>`) and take a `back` prop.
2. **Back navigation is five different things** (high). `ghost sm` Button with ArrowLeft above the title (portal-order, my-order), bottom-of-page outline button (parts-shop-order "Your shop orders"), top-right outline button to the sibling list (parts-shop-orders "Parts shop"), nothing (portal-equipment-detail, portal-location, my-equipment and my-location screenshots), versus breadcrumbs in the office app. On a phone the engineer's only way back from my-order is the small top-left ghost button; there is no bottom nav and no system-back affordance in the frame. Best: the "← parent" ghost button at the top (compact, thumb-reachable at top-left is a stretch; consider making the whole header row a back row on /my).
3. **Order lists exist in four formats** (high). Office /orders: dense DataTable with filter/saved views (clipped horizontally on mobile, `orders-m.png`: only Order and Customer visible). Customer portal: table in a card (header row, 4 columns, chevron) turning into cards on mobile. Parts-shop portal orders: header-less 4-column table. Engineer: WorkCards (big time first). The same entity (an order + status badge) shows different primary identifiers (number first vs time first vs title first) and different densities. The customer portal's card/table pair is the best-solved list of the three and mobile cards are the right idea for portals; the office table on mobile is the weak point (note for the office reviewer).
4. **Shell differences: sidebar vs slim header, and an extra top bar** (med). Office and customer: sidebar + 56px top bar; customer top bar shows the customer name + "signed in as" and four icon buttons (language, theme "Lagoon", view-as, sign-out). On a phone this squeezes the customer name to "Riedel…" and subline to "Mariek…" (portal.mobile.png header). Engineer: logo + name header, bell, kebab only. Office: bell, bug, language, theme, view-as. Brand block differs: customer sidebar shows "SHLTR Customer portal" tile, engineer header shows a hard-hat tile + engineer name, office shows org switcher with a different tile icon. Three tile icons (building, hard hat, clipboard) in the same teal square: nice and consistent as a pattern, but the label hierarchy differs (name vs org first).
5. **Customer portal on a phone has no primary navigation visible** (med). The sidebar is behind a hamburger, there are seven destinations, and "Report a breakdown" (the customer's main job) is a button on home only. The engineer portal gets away without nav because it has one list, but the customer needs bottom tabs or at least a persistent report action.
6. **Wallet / money idiom shown three ways** (med). Navy `Wallet` card (portal home, partner-programme portal, hard-coded dark), light-teal banner `Callout` (parts-shop home), plain "Available balance" rows inside the cart card, and a "Paid with parts credit" line on the shop order. Dark navy is not a theme token and looks heavy next to the light cards (`portal.png`). One WalletSummary component with a compact and a full form is needed.
7. **Banners: only the partner programme page has one** (med). It is the sole `PageBanner` in the portals; parts shop and energy have plain headers, so the module portals open in unrelated ways (hero, header+callouts, header+segmented control). The hero is nice but replaces the title; the h1 is the claim, the tab title says "Partner bonus", the nav says "Partner bonus".
8. **KPI tiles: two forms in the portal plus the office one** (med). Energy portal: lagoon header/content Card with accent bar before the number (empty body in cards without a comparison, `portal-energy-d.png` first and fourth KPI). Partner programme: tinted rectangles with a left accent border (`portal-partner-programme`). Dashboard: icon above a large number. Units needing attention on home: yet another list. Best: dashboard `StatTile` stacked layout (compact, no empty half); partner tiles are the next best.
9. **Cards: lagoon "section card" turns every small block into header band + body** (med). Header-only (portal-equipment-detail "Inspections and maintenance"), content-only (key/value card on portal-order), header+content (Units, Customer, Notes) get three looks, with and without the teal accent bar and divider. On the engineer's mobile screens, six stacked cards each with bar + divider add about 25% height of pure chrome (`my-order.mobile.png`). Plain content-only cards are fine; header band only where it earns it.
10. **Status display: EnumBadge consistently used in all three; but each portal chooses its own subset** (low/med). Good: portal and engineer lists use the same tones (Scheduled blue, In progress amber, Not accepted yet amber, Completed green, Rejected red). Deviations: order type "Project" on my-order is an icon + plain text beside the badges; "Needs service" (unit) amber vs "Not accepted yet" amber use the same tone for different concepts; priority "Normal" shows an info-blue badge on every engineer card (14 identical blue "Normal" chips, noise: only High/Urgent deserve a badge). Order numbers in status positions: portal-order shows status only top-right.
11. **FilterChips used as tabs, as filter, and for link clouds** (med). Portal orders: tabs; parts shop: category filter; portal-equipment: 22 location link chips with no counts and no selected state (indistinguishable from filter chips). Link chips should be a different shape or a list.
12. **Buttons: sizes and variants** (med). Primary teal default `h-9` (about 36px) everywhere, incl. `Save hours`, `Add note`, `Add material` on the engineer's phone; only `Complete job` and Call/Email are full-width/large. Secondary actions: ghost sm (back), outline (Your shop orders, Parts shop, Add note/Add material, Saved views), secondary missing. Primary button placed top-right (home, shop) vs below title (equipment, location) vs bottom-left (report form). lagoon gives default/outline `shadow-sm` which makes them float on the white cards.
13. **Max-widths** (low/med). Customer `max-w-[1400px]`; field `max-w-xl`; report form `max-w-2xl` left in an empty canvas; shop order card narrower than its header (`max-w-3xl`) with the status badge pinned far right: header and body don't share a width (`portal-parts-shop-order-d.png`). Equipment/location pages leave 60% of the 1,440 empty.
14. **Truncation on phones** (med). Portal order card title truncated at ~20 chars while the description wraps (portal-orders.mobile.png); equipment names truncated in units list (`Automatische deur Laboratoriu…`); customer-name header truncated to 4 letters. Engineers' cards truncate city/customer but clamp description: fine. Fix: allow title to wrap on mobile (`line-clamp-2`).
15. **Unthemed form controls** (low/med). Radio in the report form is bright blue (browser/`accent-color` default) amid teal; on-focus outlines and selected state are teal. Native look next to styled inputs (portal-report-d.png).
16. **Copy/state bugs visible in the screenshots** (low). "Placed 21 Aug 2026, 00:00 by someone" (shop order: fallback for a missing user, and a fake time 00:00). Home page "Open orders · 26" vs orders tab "Open 25" (count mismatch: the home includes the rejected order). Energy portal shows "0 kW" and flat chart for seed data (demo data, not UI).
17. **Empty states** (low). Engineer portal: plain text in cards ("No materials used yet.", "No notes yet."); customer: `Empty.Root` with icon (portal orders); parts shop: Empty without icon. Three styles for one need.
18. **Engineer vs customer cards for the same object** (low). WorkCard (engineer, rounded-xl, shadow-xs, large time) vs customer order card (rounded-md?/lagoon card, number small right): visually adjacent siblings, but radius and shadow differ (`my.mobile.png` vs `portal-orders.mobile.png`).

## 3. Worth keeping

- **Phone frame on desktop for /my** (phone-frame.svelte): honest, makes the engineer portal reviewable and demoable; keep.
- **WorkCard**: big time, number as quiet metadata, city with pin, 2-line description, 2 badges, chevron: the best list item in the product; make it the base of an `OrderCard` used by the customer portal's mobile layout and the office mobile list.
- **Customer portal orders**: table with chevron on desktop and cards on mobile from one data set; chips with counts for Open/Completed/All.
- **Full-width Call/Email buttons and the signature pad** on my-order: real mobile-first design.
- **Partner programme hero + the progress bar and tinted tiles**: the bonus tiles and "towards PLATINUM+" bar communicate well; the navy wallet as an accent is a strong brand moment, if used once.
- **Urgency radio cards with descriptions** ("It can wait for a regular visit"): great pattern for any priority picker; just theme the radio.
- **Parts shop sticky cart with balance maths** ("Balance after the order") and stock/credit badges.
- Teal accent + muted label hierarchy (`text-xs` label above `text-sm` value) in key/value blocks is consistent and readable.

## 4. Recommendations

1. Give the portals one `PortalPage` header (a `PageHeader` variant with `back` href, description, actions, `<title>`), and replace the ~17 hand-written h1s and 5 back-link styles; keep banners optional through a slot, partner programme included.
2. Extract `OrderCard` from WorkCard and use it for the customer portal's mobile rows and the office's mobile list; one list component with table (>=md) and cards (<md); allow titles to wrap and drop the "Normal" priority badge (show only deviations).
3. Mobile shell: customer portal gets bottom navigation (Home, Report, Orders, Equipment, More) or a persistent "Report a breakdown" FAB, and the top bar shows only the customer name plus one menu (language/theme/view-as/sign-out move into it), as the engineer header already does.
4. One `WalletSummary` and one KPI tile (dashboard `StatTile` stacked) for all portal and module pages; remove the hard-coded navy and the empty-body KPI cards; make header-less Card the default for small blocks and use the lagoon section header only for list/table cards.
5. On /my: make primary actions (`Complete job`, `Save hours`) large (`size="lg"`, h-11+) and sticky for the job page, group "today" with sticky day headers and a "now/next" highlight, and use real empty-state rows; theme the radio accent and set equipment/location pages to the same back pattern.
